# 采集规则集说明（source_rule）

> 更新时间：2026-10-11 ｜ 适用：abc-source-service

## 一、合还是分？——**合在一张表，分在字段**

三种来源的规则（Animeko / Kazumi / 手工）**全部存在同一张表 `source_rule`**，靠两个字段区分，引擎按字段自动分发到对应策略：

| 区分字段 | 取值 | 含义 |
|---|---|---|
| `search_mode` | `maccms` | 苹果CMS 采集接口（免浏览器，直接给直链） |
| | `xpath` | **Kazumi 格式**：XPath 选择器 + `@keyword` |
| | `css` | **Animeko 格式**：CSS 选择器 + `{keyword}` |
| | `api` | 通用：HTTP + JSONPath |
| `name` 前缀 | `[Kazumi] xxx` | 来自 Kazumi 规则库 |
| | `[Animeko] xxx` | 来自 Animeko css1.json |
| | 无前缀 | 手工规则 |

**后面的链路完全共用**：不管哪种模式，都是
`搜索 → 分集 → （浏览器解析）→ 直链 → 流代理 → 前端播放`。
需要浏览器的规则统一 `browser_resolve=1`。

## 二、规则文件（三个 SQL，可叠加执行）

| 文件 | 内容 | 条数 |
|---|---|---|
| `sql/source_rule.sql` | **建表** + 手工实测规则（maccms 量子资源、7sefun） | 2 条 enabled |
| `sql/animeko_rules.sql` | Animeko web-selector 全部源 | 18 条（6 可用） |
| `sql/kazumi_rules.sql` | Kazumi 规则库 | 86 条（16 可用） |

执行顺序：先 `source_rule.sql`（建表），再另外两个。

## 三、实测结果（关键词「火影忍者」，2026-10-11）

| 来源 | 总数 | 可用(enabled=1) | 不可用原因 |
|---|---|---|---|
| 手工 | 2 | 2 | — |
| Animeko | 18 | 6 | 被墙/403/超时 |
| Kazumi | 86 | 16 | 站点失效/XPath 过期/连接失败 |
| **合计** | **106** | **24** | |

> 仅"搜索阶段"判定：`enabled=1` = 搜索能返回结果。真正可播还需分集解析 + 直链解析，
> 请用下方自测接口复测。

## 四、自测 / 导入接口

```bash
# 批量测全部规则（withBrowser=true 会跑浏览器取直链，慢）
GET  /api/source/test/all?keyword=火影忍者&withBrowser=false

# 测单条规则
GET  /api/source/test/rule/{id}?keyword=火影忍者&withBrowser=true

# 运行时导入（免改 SQL）
POST /api/source/import/animeko   body=Animeko css1.json 原文
POST /api/source/import/kazumi    body=Kazumi 插件 JSON（单个或数组）

# 端到端：搜番→择优→解析直链
GET  /api/source/test?title=火影忍者&ep=1
```

## 五、注意事项

1. **规则会过期**：站点改版会让 XPath/CSS 失效（Kazumi 仓库里 7sefun 就已过期）。所以本设计强调
   "规则是数据 + 带自测 + 带健康度（success_rate/health_status）"，这是论文里"规则可运维性"的素材。
2. **KazumiRules 抓取用镜像**：`raw.githubusercontent.com` 被墙，改用 `cdn.jsdelivr.net/gh/Predidit/KazumiRules@main/`
   或 Kazumi 自带的 `raw.gitcode.com/gh_mirrors/ka/`。
3. **JsoupXpath 限制**：不支持 `not(contains())` 组合选择器，会让选择器静默返回 0。写 / 调 XPath 时保持简单。
4. **合规**：仅本地研究，勿公开部署或分发。
